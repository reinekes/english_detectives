# Baker Street — план реализации прототипа

> **Для исполнителя:** выполнять задачи последовательно; независимые тексты и визуальные материалы можно готовить параллельно. Для реализации применять `superpowers:subagent-driven-development` или `superpowers:executing-plans`. Чекбокс означает проверенный результат, а не намерение.

**Цель:** дать пользователю красивый законченный детективный эпизод на английском с переводами, сохранениями и объяснимой развязкой.

**Архитектура:** статический клиент с отделённым контентом дела и версионированным состоянием в `localStorage`. Все игровые решения принимаются локальными правилами; сервер, аккаунты и LLM для прототипа не нужны.

**Стек:** HTML, CSS, JavaScript без этапа сборки, Web Storage; необязательные Web Speech и Web Audio.

**Спецификация:** [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md). **Сюжет:** [CASE_DESIGN.md](CASE_DESIGN.md).

**Итог исполнения, 2026-10-26:** все пять задач реализованы, 16 тестов прошли, оба финала пройдены в браузере, приватная версия опубликована. Подробная фактическая проверка: [PROJECT_LOG.md](../PROJECT_LOG.md). Незакрытые пункты ниже обозначают только явно названные пределы дополнительной проверки, а не отсутствующие функции.

## Общие ограничения

- Один эпизод `The Ashford Affair — The Last Letter`, четыре подозреваемых, шесть улик, три дедукции.
- Основной язык — английский около B1; русский перевод открывается по запросу.
- Порядок открытия выводов определяется уликами; неправильная попытка не уничтожает прогресс.
- Финал требует три обязательные улики и три дедукции; игрок выбирает подозреваемого и три доказательства, затем подтверждает обвинение.
- Основной маршрут доступен на ширине от 360 CSS px, с клавиатурой и без аудио.
- Все изменения и фактические проверки фиксируются в `PROJECT_LOG.md`; сохранять различие между целью и проверенным результатом.
- План не является подтверждением готовности. Публиковать статус только после проверки результата.

## Особое внимание при проверке

1. Повторный осмотр предмета не дублирует улику; переходы и перезагрузка сохраняют прогресс.
2. Раннее посещение доски и неверный ответ не обходят условия финала.
3. Повреждённое сохранение и отказ хранилища не оставляют пустой экран.
4. Телефон, длинный текст и клавиатура не делают кнопки диалога недоступными.
5. Отсутствие речи/аудио не блокирует расследование; экспорт журнала остаётся читаемым.
